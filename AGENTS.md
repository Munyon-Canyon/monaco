## Learned User Preferences

- Keep `just` recipes minimal: `just build`, `just test`, `just run`, `just stop`, and `just reset` per app (`backend` or `mobile`), plus root variants, `just migrate db`, `just install` (clone setup), `just encrypt`, `just decrypt`, `just show-env` (dotenvx on `.env.local`; encrypt/decrypt also touch `.env.production` when present; show-env is `.env.local` only via `with-dotenv-local.sh`). `just relayer balance` was deleted with the legacy backend in M7 and returns with the funding module. `just build backend` writes `bin/api`, `bin/worker` and `bin/monacoctl`; `just run backend` starts api (`:8080`) and worker (`:8081`, health only) and `just stop backend` SIGTERMs both. `just run backend` starts Compose `postgres` and `nats`; `just test backend` starts `postgres-test` (`monaco-postgres-test`, port 54323, tmpfs, durability off) if it is down. `just reset` = stop all + wipe every Compose volume (Postgres and NATS); `just reset db` = Postgres only, NATS data kept. `just migrate db` applies pending migrations to the `.env.local` database; `just run backend` never migrates, and a database behind the binary stops boot with `db_schema_behind`. `just killports` kills the api and worker listeners (8080, 8081), not Compose Postgres (54322). Ctrl-C on `just run`, or a failed iOS build, stops the backend too. `just stop mobile` and full `just reset` uninstall `com.monaco.app` to clear Privy session (`scripts/stop-mobile.sh`): in a linked worktree only on its own sims and builds; in the primary checkout on every sim except live worktrees', deleting sims of removed worktrees.
- When the user says "test mobile" or runs `just test mobile`, run host `swift test` in `packages/mobile-core` (fast, deterministic; no iOS Simulator or `xcodebuild test`). `just build mobile` / `just run mobile` / `scripts/ios-build` / `./scripts/ios-sim` use `scripts/resolve-ios-sim.sh`: in a linked worktree its own sim `Monaco <lane>` (created on first use; builds go to the checkout's `.build/DerivedData` under RAM-sized `xcode-lock.sh` slots), in the primary checkout SimSlim when ready, else stock sim with stderr warning; `MONACO_SIM_UDID` overrides both (`docs/how-to/local-simulator.md`). Do not boot a sim for unit tests. Never commit a UDID. Never `simctl erase`. Agent tap-through may use `.cursor/skills/ios-simslim-fast-qa/SKILL.md` or MobileBuildMCP with `--simulator-id` from `scripts/gold-sim-udid.sh` (the worktree's own sim in a lane; in primary fail-loud if `SIMSLIM_UDID` is unset; not used by human `just run`). Do not drive taps with AppleScript, CGEvent, or coordinate hacks. For `just test backend`, use stubs/mocks only—never hit the live Jupiter API; trim property tests that run longer than ~2 minutes. Tests must not hardcode wall-clock dates that age out (freshness/staleness checks): stamp fixtures relative to `time.Now()`.
- App directories are `apps/backend` and `apps/mobile` by intentional rename; do not refer to or recreate `apps/api` or `apps/ios`. The iOS Xcode project/scheme may stay named `Monaco` under `apps/mobile`.
- Use dotenvx for repo secrets (`.env.local` for dev, `.env.production` for prod). Teammates share encrypted `.env.local` plus `.env.keys` in the clone root (gitignored). Without `.env.keys`, `with-dotenv-local.sh` decrypts from an exported `DOTENV_PRIVATE_KEY_LOCAL` / `DOTENV_PRIVATE_KEY` (how cloud agents get secrets). Backend `just run` / `just test backend` re-exec under `scripts/with-dotenv-local.sh`. Mobile Privy: `ensure-ios-privy-config.sh` → xcconfig; `with-ios-privy-env.sh` / `./scripts/ios-sim` → `SIMCTL_CHILD_*` at simctl launch only (relaunch from sim home icon drops creds). iOS scripts require `PRIVY_APP_CLIENT_ID` from decrypted `.env.local`—legacy `PRIVY_AUTH_ID` in plain `.env` must not substitute. Justfile `dotenv-load` only reads plain `.env`. Repo onboarding must be machine-agnostic—another dev clones, decrypts, and runs the same way; prune machine-specific docs or commands.
- Ship changes as Graphite stacks of small PRs, never one large PR. Graphite (`gt`) is a required tool installed by `just install`. Create branches with `gt create`, amend with `gt modify`, push with `gt submit --stack --no-interactive --draft`, and never open a stacked PR with `gh pr create`. Each PR builds and passes `monacoctl agents check` on its own; CI runs the full suite on the top PR of a stack only, so lower PRs are proven by `agents check`. Each PR stays under 1000 changed lines (CI enforces it; only a human adds the `large-pr` label); split an oversized branch with the `distribute-stack-changes` skill. PR titles say what the PR changes, present tense, with no issue number or commit-type prefix (link the issue under Why), and bodies follow `.github/pull_request_template.md` (pr-summary style: TLDR, Why, What changed, Proof, What came up, Reviewer focus), set with `scripts/pr-body.sh <pr> "<title>" <file>`, which runs the PR format check and marks the draft ready. Stacks build on the trunk `staging` (the default branch) and land through the Graphite merge queue. Always land: right after `gt submit` and `scripts/pr-body.sh`, run `monacoctl agents land-stack <top-pr>` once without asking, unless the user says in the current conversation not to land or queue, then follow it with `monacoctl agents watch` under Monitor. If stage 1 is still running, `land-stack` arms the stack, and `agents watch` lands it once stage 1 passes, or prints `armed stack #<top> disarmed: ...` when it fails. The verifier's `verify` status is advisory: landing does not wait on it. It adds the `merge-queue` label to every PR of the stack, and the queue squashes each PR into one commit on `staging` (title, ` (#N)`, then the body), so a landed PR shows as closed, not merged, and `Closes #N` in its body closes the ticket. Never `gh pr merge` (direct or `--auto`), never `gh pr edit --base`, no `Lands stack:` line, no `<feature>-checkpoint-<N>` branches, and never add `merge-queue` or `fast-track` by hand (`fast-track` is human only, for PRs under 100 counted lines). If a stack drops out of the queue, fix it with `gt modify` and `gt submit --stack`, then rerun `land-stack`. To change a queued stack, run `monacoctl agents dequeue <top-pr>` first; the agent guard hook blocks `gt submit`, `gt modify`, `gt restack` and `git push` on a stack while any of its PRs carries `merge-queue`. Before a force push, confirm the remote branch has no commits the local stack lacks. Rules: `docs/architecture/backend-platform.md#pull-requests-small-and-stacked`.
- Never weaken a test gate to get green: no new `coverage.exclude`, `mutants.allow` or `.golangci.yml` exclusion lines, raised perf baselines, edited golden files, added `t.Skip`, or deleted test functions. The `gate-changes` CI job flags such a PR with a warning annotation (it stays green and does not block); only a human adds the `gate-change-approved` label that silences it, and the author explains the change under Reviewer focus (`docs/architecture/ci.md#what-runs-where`).
- GitHub issue and milestone ticket bodies should follow the write-ticket format (Context, Problem, Proposal with Implement exactly, acceptance criteria, verification commands, Done when) with minimal agent discretion.
- Parallel milestone implementation should use worktree-orchestrate with Composer 2.5 subagents unless another model is explicitly requested; run unrelated tickets in parallel in separate git worktrees (one lane per feat branch), not serialized on one checkout; split mobile vs backend tickets to separate agents; parent orchestrator owns the queue and must not spawn nested orchestrator subagents; when multiple agents overlap on one task, keep whichever is furthest along only.
- Ticket/feature work runs in git worktrees under `.worktrees/`; never dirty the user's primary checkout (often `main`)—land on named integration branches in the worktree, not by checking out the primary tree; subagents must cd and use absolute paths inside the worktree because Task inherits parent cwd. After landing, remove the worktree and put primary on the named branch with a clean tree matching HEAD so the user can build/test from repo root via `git checkout <branch>`—do not leave work only in `.worktrees/` or let primary disk revert the branch.
- For Privy dashboard verification or client settings during agent QA, use the attached Privy browser tab; do not ask the user to make dashboard changes. Prefer Privy API/dashboard ops over ad-hoc product PATCH-in-loop for legacy wallet signer fixes.
- Verification runs in three stages, per `docs/architecture/backend-platform.md#verification-scope`: agents run `monacoctl agents check` on every PR, CI stage 1 runs the full suite on the top PR of a stack (lower PRs' `ci / ci-ok` passes with every job skipped), including the macOS `ios` job (app build plus MonacoTests) when `apps/mobile`, `packages/mobile-core` or `packages/flows` changed, and the Graphite merge queue runs only build, vet, tidy and generated files before anything lands on `staging`. Every hour, when `staging` moved, `staging.yml` runs the full suite again as an advisory indicator that gates nothing (it ran on every push until #2950, which left PR runs waiting for the free plan's 20 concurrent jobs). The operator approved this split, so it is not skipping. Ticket Done-when, milestone manual verification, `just build mobile` and gold-sim QA still apply when the change touches what they cover. Every PR that touches `apps/mobile/**` must pass a local `just build mobile` and the MonacoTests run (`-only-testing:MonacoTests`) before it is pushed, and Proof cites both. Every PR that touches Darwin-only code in `packages/mobile-core` must pass a local macOS `swift test` before it is pushed. Never skip or shrink a check in that set unless the user explicitly says to skip in the current message.
- When the user says they'll build or run themselves, verify code changes only and skip sim, build, or run in that session unless they ask in the current message.
- Product UI: prefer toasts over main-UI popups or banners for action confirmations; never hyphenate wallet addresses; show human-readable stock names or symbols, not raw mint addresses or "xStock" branding. User-facing copy uses "cabal" (not club/group), and so do new API routes, Go types, tables and event subjects (`/v1/cabals/{id}`; see `docs/architecture/backend-platform.md#decided`). Use "deposit" for inbound USDC to platform balance; "fund this cabal" for sweeping platform USDC into a group treasury; partial cabal stake sales use a sell flow without leaving the group.
- For a CI flake with no code change, rerun only the failed jobs with `gh run rerun <run-id> --failed`; don't rerun the whole run. A fix commit starts a new run on its own; don't also trigger a rerun.

## Learned Workspace Facts

- Monaco is a mobile app for group treasury investing in tokenized stocks (xStock via Jupiter swaps). Apps live at `apps/backend` (Go API) and `apps/mobile` (Swift/iOS). Host-runnable Swift unit tests live in `packages/mobile-core`. README is clone/run/how-to only; product and ops details live under `docs/`, starting at `docs/index.md` (product rules in `docs/product.md`, system design and money flows in `docs/architecture.md`, history in `docs/legacy/`). The existing Groups tab lists all groups (joined and unjoined)—not a separate bottom-nav groups feature.
- Go and Swift integrate via HTTP API contract only; mobile never calls xStocks, Jupiter, Pyth Hermes, or Solana RPC for product flows (plus Privy Swift for auth/wallets). The legacy backend's routes, such as `GET /v1/groups/{id}/view`, are archived in `docs/legacy/api.md`; the rewrite's contract is `apps/backend/api/openapi.yaml`.
- The dev database container `monaco-postgres` keeps `fsync`, `synchronous_commit` and `full_page_writes` on. `apps/backend/deployments/compose.yml` (included by the root `docker-compose.yml`) pins them, and `scripts/agent-guard-dev-db.sh` (a Claude Code PreToolUse hook in `.claude/settings.json`) blocks `ALTER SYSTEM`, `pg_resetwal` and durability-off flags aimed at it. Benchmarks and durability experiments use a throwaway container on another port, removed afterwards. Recovery from a broken dev database is `just reset db`, with the user's go-ahead.
- Local development database is Docker Compose Postgres; do not use hosted or production Supabase for local testing. App `DATABASE_URL` is `monaco`. The legacy migrations and the derived `monaco_test` database were deleted with the legacy backend in M7.
- Privy handles auth and per-user wallets; one Privy wallet per user—reuse existing wallet on login, never recreate. OTP sendCode (SMS/email) is Privy-direct to auth.privy.io; Monaco backend only after `POST /v1/auth/session`—no API traffic during OTP is expected. Inbound USDC stays in the member Privy wallet as platform balance; platform balance shown to users is on-chain USDC minus in-flight fund-to-cabal intents—not ledger-only. User-initiated fund-to-cabal sweeps an exact amount from member wallet to group treasury. Deposit UI shows the user's copiable Privy deposit address; no in-app amount submit on deposit. For local dev/testing, USDC sent from the developer's own Phantom wallet to that deposit address is picked up by the deposit poller without agent MCP (flow 5, returning with the funding module).
- Leaderboard and P&L (within a group and across groups) are core product focus, with portfolio views and partial USDC redeem. Group member board lists every `group_member` regardless of deposit or P&L. Transaction history includes group buys and sells plus pending and failed states.
- `PHANTOM_APP_ID` belongs in Cursor Phantom MCP config, not Monaco `.env` — Phantom MCP is an agent test harness with a separate wallet from Privy product wallets. The shared QA pot (`QA_POT_PRIVATE_KEY` in the encrypted `.env.local`, used through `monacoctl qa pot` and `monacoctl qa fund`) is the default QA funding wallet and the only one cloud agents can use; Phantom MCP stays as a per-machine alternative. Refund leftover agent-test USDC with an in-app withdrawal to the wallet that funded the run when QA funding runs finish.
- Milestone product work merges to the one trunk, `staging`; the operator promotes `staging` into `main` with a merge commit (`docs/architecture/ci.md#feature-branches`). Post-M5 lanes are separate milestones for treasury yield accrual and in-platform agentic trading (strategy agents emit intents; backend Privy-signs; no external bot custody).
- Do not track `.cursor/hooks` in git; local Cursor hook state stays gitignored.
- Claude Code on the web (cloud agents, `CLAUDE_CODE_REMOTE=true`) runs in a Linux container: Go, Swift, Docker, `just`, and `psql` are installed, but no Xcode or iOS Simulator. The environment setup script is a pasted copy of `scripts/cloud-setup.sh` (Swift toolchain, `just`, `dotenvx`, cache warm-up); edit the file, then paste it into the environment config again. The cloud environment sets `DOTENV_PRIVATE_KEY` as an environment variable (no `.env.keys` in the clone). The tracked `.claude/settings.json` SessionStart hook (`.claude/hooks/session-start.sh`) installs the pinned atlas and sqlc into `.bin/` (via `scripts/install-atlas.sh` and `scripts/install-sqlc.sh`, since `just install` is interactive macOS) and starts `dockerd` because the container doesn't run it and setup-script processes don't survive into the session; the hook no-ops locally. In cloud sessions `just test backend` and `just test mobile` both work; `just build`/`run mobile` and sim QA do not. `packages/mobile-core` must keep building on Linux: guard `import FoundationNetworking` with `#if canImport(FoundationNetworking)`, keep Darwin-only URLSession APIs (e.g. `waitsForConnectivity`) under `#if !canImport(FoundationNetworking)`, and skip only assertions tied to Darwin-only URLSession/NSError behavior on Linux.
- Product uses Solana mainnet (not devnet) for RPC, USDC, and chain operations.
- The backend needs `DATABASE_URL`; Privy app id/secret/client id; `PRIVY_AUTHORIZATION_PRIVATE_KEY`, `PRIVY_AUTHORIZATION_KEY_ID` (Privy dashboard quorum id, not derivable from the private key), `RELAYER_PRIVATE_KEY`, and RPC. Privy signing uses one app authorization keypair in env; member wallet create must set `owner` plus `additional_signers` with that quorum id at create time; treasuries are app-owned. iOS bundle `com.monaco.app` must be on the Privy iOS client or OTP `sendCode` returns 403 `invalid_native_app_id`. Pre-fix wallets without signers need one-time recreate or owner-signed update — not OTP PATCH as the product path. In staging and production, api and worker boot fails if the relayer fee payer holds ≤0.001 SOL (`relayer.CheckBoot`); relayer is app-owned in `.env.local`, not Privy (pubkey in README).
- The legacy backend's tables (`sweep_tx_log`, `share_ledger`, the M2 Deposit/Withdrawal/Transaction/Position tables, the M3 `transactions` swap rows) were deleted with it in M7; their history is in `docs/legacy/`. The rewrite's tables, owners and money rules are in `docs/architecture/backend-platform.md`. Swaps stay backend-only on Jupiter Swap API v2 on mainnet; the treasury signs with its app-owned Privy wallet + `PRIVY_AUTHORIZATION_*`; xStocks mints resolve via the `api.xstocks.fi` public assets API.
- Group treasury value is total across USDC and all tokenized stock holdings, not cash alone; propose-buy amount cannot exceed treasury total.
