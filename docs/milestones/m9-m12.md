## Decisions

### How the work was split

- **07:16** The M9 to M23 tickets had no `Touches` or `Base branch` in their header, so `monacoctl agents batch` deferred them. Dispatches used `--urgent`. That skipped the overlap check `batch` exists to run, and the cost showed up at landing: see "One chain" below.
- **07:16** Five module-root tickets went out at once on `opus`. Five owners running stage 0 together pushed the 1-minute load past 80, and every package budget failed. The M7 log records the same mistake at 08:28 on 2026-09-29.
- **08:33** Later owners ran as build-only lanes: they built, linted and tested their own packages, and the root ran stage 0 one branch at a time, submitted and set the bodies. It kept the machine usable and made the root the bottleneck.
- **09:08** Tickets with a complete "Implement exactly" list went to `sonnet` owners with an `opus` verifier, at the operator's request to spend fewer tokens. Thirteen tickets have had one: #531, #533, #543, #546, #554, #572, #1072, #1073, #1074, #1075, #1097, #1100 and #1114.
- **16:30** Back to the documented procedure for every new dispatch, after reading the M7 and M8 logs against this run:
  - Tickets get `Base branch` and `Touches` before dispatch (done for #572 and #564), and go through `batch`. `--urgent` is for a fix that unblocks others.
  - Owners run stage 0, submit and set bodies themselves, as `docs/agents/owner.md` says. The two running owners were told.
  - The root holds a dispatch while the 1-minute load is over 12 and dispatches in a rolling window.
  - The verifier lands a passing stack.
  - What changed on the platform since a ticket was written goes into the ticket body with a comment, not into a private note to its owner (#572).

### One chain for six module-root stacks

- **09:05** Every module's first ticket edits the same files: `internal/errs/codes.go`, the OpenAPI `ErrorCode` enum, the Swift exhaustive switch, `CHANGELOG.md`, `sqlc.yaml`, every sqlc `models` file and `atlas.sum`. Six stacks built on one tip conflict six ways.
- **09:20** The six stacks became one Graphite chain in migration order: identity, treasury, market, trading, governance, ranking. Each conflict was resolved once.
- **09:20** Error codes follow identity's shape: a const block and a `<module>Rows()` function per module, registered in `rowGroups()`. `platformRows()` stays byte for byte the same, so the allocation baseline of `httpx.Problem` does not move.
- **09:25** Generated files are never merged by hand. A local `.git/info/attributes` takes the base side of every generated file during a rebase, and one script regenerates them on each branch. A check compares each branch's own diff before and after a restack, so a hand-written change cannot be dropped with a generated one.
- **09:40** Trading's migrations were renamed to `20260930080200_trading.sql` and `20260930080300_swap_views.sql`. Their first version number was the same as the market assets migration's.
- **15:50** The second chain (#554, #553, then #531, #533, #543) was restacked the same way. Its three hand merges are in "What broke" below.

### The ticket audit

- **17:20** An audit of the seventeen M9, M10 and M12 tickets that wait on the running ones checked every header, code path and command named in each body against the tree at the feature-branch tip. Each ticket got its header (`Base branch`, `Touches`, missing blockers), its stale lines replaced, and a comment that says why. Facts that repeated across tickets became rules in the comments: `_OK` is the outcome suffix `flows.TestName` writes; faultpoint names are the five registered ones and `before-commit` already fires in `uow.Do`; a handler is typed to one event type and handler names are unique, so a durable with several event types has one handler per type; a consumers cell may name a handler or its durable; the consumer generator refuses underscores; a consumer runs inside Dispatch's transaction; verify writes evidence to the ignored `.verify/` directory and `flows check` reads none of it.
- **17:35** Flow ids keep #509's sub-rows (`01a` to `01e`, and `23a` for the photo route): #1172 widens `flows.Parse` to one letter after the digits. Numbering them 29 and up would have left #509's rule dead.
- **17:40** Query ports move to leaf `<module>/port` packages (#1173). The M9, M10 and M12 reads form cycles (identity and funding, funding and treasury, treasury and cabal), and with the port in the module root the Go import graph cannot compile them. `module.Deps` carries no ports and PR #1105 settled that a reader builds the provider's port itself, so a `cmd` hook does not exist. A `port` package imports only its module's `sqlc` and `domain`; the depguard generator gets a third wall for it. #556, #562, #563, #564, #578, #579, #608, #609 and #642 now wait for #1173, and their "`cmd` wires" sentences are gone.
- **17:45** `CodeInsufficientFunds` is declared by #579 (five tickets use it and none declared it). Both `GET /v1/me/balance` and `GET /v1/me/txns` are `x-allow-restricted`, since a banned user must see both to withdraw. Each ticket adds its own `qa-*` Privy fixture. #572 points the verify stack at the `/privy` fake and #564 at the `/rpc` fake. #601 gets a per-operation `x-max-body-bytes` extension for the 2 MiB photo. #640's nudge interval becomes a config key so verify can set it to a second. #642's photo purge is a poller with `users.photo_purged_at`, because an outbound call cannot run inside a consumer's transaction and `OnCommit` has no retry. #578 and #579 drop #556 from their headers, since their bodies already say the last PR waits for it.
- **18:05** `verdict carry` decides itself whether a restacked PR needs a new review: it compares the stable patch-id, so the three Swift-switch PRs whose restack only changed whitespace carried, and only the two `CHANGELOG.md` PRs were reviewed again.
