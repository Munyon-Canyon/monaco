# Standing orders

These are the rules every agent and person follows in the milestone workflow. They came out of the M7 run, where the operator gave 31 numbered orders during one night and day. This page keeps the ones that still need judgment, one rule each, with the reason and the incident behind it. A dispatch prompt names this page, and the [owner](owner.md) and [verifier](verifier.md) briefs link it.

Hooks and CI checks now enforce many of the original orders, so they are not numbered here. [Enforced by tooling](#enforced-by-tooling) lists them. The Claude Code hooks do not run in a plain terminal, so a person owning a ticket follows that list too. [Superseded](#superseded) lists the orders that no longer apply. The [M7 closeout log](../milestones/m7-closeout.md) records the decisions behind them.

To change a rule, edit `docs/agents/rules.yaml` and run `go generate ./...` in `apps/backend`; this page renders from it. Say why under "What came up".

## Orders

<!-- BEGIN GENERATED rules:standing-orders (docs/agents/rules.yaml) -->
- Stacks build on the trunk `staging` (the default branch) and land through the Graphite merge queue.
- Always land: right after `gt submit` and `scripts/pr-body.sh`, run `monacoctl agents land-stack <top-pr>` once without asking, unless the user says in the current conversation not to land or queue, then follow it with `monacoctl agents watch` under Monitor.
- If stage 1 is still running, `land-stack` arms the stack, and `agents watch` lands it once stage 1 passes, or prints `armed stack #<top> disarmed: ...` when it fails. The verifier's `verify` status is advisory: landing does not wait on it. It adds the `merge-queue` label to every PR of the stack, and the queue squashes each PR into one commit on `staging` (title, ` (#N)`, then the body), so a landed PR shows as closed, not merged (merged when it landed on stage 0), a `revert-<top>` PR from `agents watch` is landed, not fought, and `Closes #N` in its body closes the ticket.
- no direct merge: enforced by `hook:rule_merge_needs_verify`.
- no base edits: enforced by `hook:rule_edit_base`.
- No `Lands stack:` line and no `<feature>-checkpoint-<N>` branches.
- queue labels: enforced by `hook:rule_queue_label`.
- If a stack drops out of the queue, fix it with `gt modify` and `gt submit --stack`, then rerun `land-stack`.
- To change a queued stack, run `monacoctl agents dequeue <top-pr>` first.
- queued stack guard: enforced by `hook:rule_queued_stack`.
- Land on `staging`, always through `land-stack`. Only the operator merges into `main`: `main` changes only through a promotion PR from `staging` that the operator merges with a merge commit. [Old flow and new flow](../how-to/ship-a-ticket.md#old-flow-and-new-flow) lists what changed from the checkpoint branches. Why: a promotion carries exactly what landed on `staging`. A PR based on `main` puts commits on `main` that `staging` lacks, and the next promotion must merge them back first. Incident: a CI budget fix (#836) was based on `main`, and `main` then held commits the feature branch lacked. Checkpoint 3 needed a merge-back PR (#892) before it could open.
- Work only in your assigned worktree under `.worktrees/`. `cd` into it first and use absolute paths. Never change the primary checkout. Why: owners run in parallel on one clone. The primary checkout is the operator's build tree and must stay on its branch, clean. Incident: an agent's shell resets its working directory between commands, so a relative path can land in another agent's tree.
- Only the root restacks, and one stack at a time. Update the trunk with `gt sync --no-interactive --no-restack`, then restack the target stack with `gt restack --upstack` in its worktree. Build every branch of the stack afterwards. Why: a restack moves branches that an owner may be building on. Incident: a plain `gt sync` restacked owners' in-progress branches twice (the #479 stack and the #831 F stack). A clean textual restack of #482 still failed to compile, because the tip had renamed a helper.
- An owner stops after it arms its stack. It pushes drafts, runs `scripts/pr-body.sh` for each PR, runs `monacoctl agents land-stack <top-pr>` once, and exits with its PR URLs, heads and decisions. It never waits on CI and never merges. Why: the root and the verifier own everything after the push. A waiting owner holds a lane and burns its context. Incident: the lane cap counts every owner not marked exited. Finished owners that kept running blocked new dispatches until the root ran `monacoctl agents exited`.
- A verifier runs on another model, reviews the diff against the ticket and runs no tests. It reads `gh pr checks` once and fails a PR only for a real defect: wrong behavior, a missing acceptance item the PR claims, a CI-breaking change or a format violation. Its report says exactly what to fix. Why: a second model catches what the owner's model misses. CI already runs the tests. Incident: the #537 verifier caught Jupiter's `priceImpactPct` read as a fraction instead of a percent. It would have refused every real trade.
- Use `opus` for owners and `sonnet` for their verifiers. After three failed `opus` attempts on one problem, try `fable` once at medium effort, then park the ticket. Park with a comment that says what was tried. Why: `opus` and `sonnet` keep cost and behavior predictable. One stronger attempt is cheaper than a parked ticket. Incident: three `opus` owners could not find the #838 NATS flake. One `fable` attempt root-caused it to a race in `nats-server` and fixed it.
- Sign every commit and PR body. Commit messages end with a `Co-Authored-By:` trailer that names the model. PR bodies end with the Claude Code line from the template. Why: a reviewer can tell which model wrote a change and weigh the review for it.
- Write tests that repeat. Stamp fixtures relative to the current time, never with a hard-coded date. Fake every external API; never call live Jupiter. Reset global registries and shared servers between runs. Why: the `flake` job reruns each changed test file 20 times, and a date that ages out fails a test months later with no code change. Incident: `TestRegisterLedgerCheck` accumulated entries in a global registry and ejected #904 under the 20 reruns. `TestBusApply` shared one NATS server and failed at `-count=2` (#930).
- Say what the PR changes in its title, and record every decision under "What came up". The last PR of a ticket lists everything only the operator can do under `## Needs from Logan`, or says "Nothing." Why: the operator reads the bodies, not the transcripts. A decision that is not in a body is lost. Incident: the #490 owner left an eval result for the operator to judge. The root judged it and changed the section to "Nothing.", which saved a round trip.
- Fix a failed check by its cause. Rerun only the failed jobs once for an infra flake, with `gh run rerun <run-id> --failed`. Fix a PR format failure caused by the body by editing the body. A fix commit starts its own run, so do not also rerun. Why: a rerun replays the original event, including the body the PR had then. Incident: reruns of #895 and #962 replayed the empty body from when the PR opened and failed again. Docker Hub, Go proxy and `curl` 500 errors ejected #843, #933 and #934, and each landed on requeue with no code change.
- Land a fix ahead of the PRs it unblocks. When a defect on the tip ejects PRs, stop requeueing them. Land the fix first, then requeue the rest behind it. Why: a queued stack tested without the fix fails again. Incident: #931, #933 and #934 were queued ahead of the teardown fix #952. They were dequeued and requeued behind it.
- Hand work on through GitHub, not through one machine. Before you stop, push every branch, keep the draft PR's "What came up" current and post the next step on the ticket. Keep the milestone decision log committed. Why: any engineer must be able to pick up a ticket or a milestone from a fresh clone. Incident: at the M7 closeout the owner records, standing orders and decision log existed only on the operator's machine. The handoff had to tell the next orchestrator to re-dispatch in-flight tickets instead of resuming them.
- Before you stop or replace the backend on `:8080` or `:8081`, ask the orchestrator. That covers `just stop backend`, `just run`, `just reset` and serving a worktree branch there. Ask even when the user wants the branch backend, and use other ports for your own checks. Why: those ports are shared QA infrastructure, and a restart cuts off whichever session is mid-request against them.
- Arm only your own PRs. When `agents watch` reports another lane's stack as green but not armed, message the orchestrator with the PR and the evidence before you run `land-stack`, and wait for a go-ahead. Why: a missing arm can be a deliberate hold, and the watch logs a deliberate `agents dequeue` the same way it logs a lost arm.
- Write `closes`, `fixes` or `resolves` followed by an issue number only in the last PR of a ticket, even as a negation or a passing mention. In every other body, say "the last PR of #N". Before `scripts/pr-body.sh`, grep the body file with `grep -niE "(close[sd]?|fix(e[sd])?|resolve[sd]?) #[0-9]+"`. Why: GitHub closes the ticket on squash for a closing keyword anywhere in the body, so an early mention hides an unlanded PR from the board.
- Run every agent that writes code (ticket owners, bug fixers, runner changes) on `sonnet`, and keep planning, review and landing in the root. Pass `--model sonnet` to `monacoctl agents dispatch` and `model: sonnet` on `Agent` calls. Why: the operator asked for this during the 2026-10-06 overnight run, after Opus owners had been spawned. It overrides the Opus default in the pstack model sheet.
- For a milestone run, give each ticket or ticket group its own herdr workspace with an Opus session that orchestrates Sonnet coders and submits and lands its own stack. The main session supervises the lanes and the CI manager, and does not run owners as in-session subagents. Dispatch one ticket at a time (`agents batch <n>`, then `dispatch <n> --model opus`) so Touches overlaps inside a lane do not defer tickets. Why: the operator wants each lane visible in the herdr sidebar, with Opus orchestrating and Sonnet coding, and the same holds for the CI manager's tickets.
- In `packages/mobile-core`, write a new test on a `@MainActor` XCTestCase as `async throws`, never as a synchronous `throws`. To check, build the tests in the Swift Linux container and dump the test list as JSON; exit code 134 means the discovery crash. Why: the Linux XCTest runner force-casts a synchronous isolated test to a non-isolated type and aborts discovery, and macOS stage 0 passes, so only stage 1 shows it.
- When a check, journey run or CI job fails twice at the same step, stop rerunning. Diagnose from the code, the accessibility tree or the logs, decide whether the setup or the code is wrong, and fix that before the next run. Never rerun one change at a time with a full rebuild each time. Why: a journey owner reran one failing step about eight times at roughly 3.5 minutes a run, and the operator called the loop unacceptable.
- Prove a paging or batching rule with the smallest N that spans several pages, such as 250 rows at a page size of 100 for exactly 3 calls. Do not seed thousands of rows, and shrink any test that seeds more than about 500 before it ships. Why: a 10,000-wallet test saturated the shared test Postgres and failed other lanes' stage 0 for hours.
- After `monacoctl agents dispatch` creates a worktree, open it with `herdr worktree open --cwd <repo root> --path <worktree> --label "<n> <short name>"`, and close that workspace when the worktree is removed. Why: dispatch and `git worktree add` do not open a herdr workspace, so the worktree stays out of the operator's sidebar.
- Run journey QA on one booted simulator and switch actors in the app instead of booting a simulator per actor. Run a journey's steps in one continuous pass, not one relaunch per step. No more than 2 simulators may be booted across all sessions: check `xcrun simctl list devices booted` first, shut down extras, and drop a simulator on its first crash loop. Why: four booted simulators pushed machine load to 174 and slowed every lane.
- Before you commit Go, run the pinned `golangci-lint run ./<pkg>/...` from `apps/backend`, use a fixed `time.Date` in tests and write no Go comments. A refusal caused by your own change is yours to fix; retry once, and report the exact lines at once if it stays refused. Wait on your own check by pid, never `pgrep 'agents check'`, which matches other lanes' checks. The root takes over an owner whose files sit unchanged for 10 minutes with nothing running. Why: owners wrote correct code and then stalled without a report on a refused pre-commit, and two sat for more than 30 minutes while the critical path waited.
- On a branch that changes the shape of an on-disk record every lane reads, such as `.git/.monaco/agents/<n>.json`, run `land-stack`, `dequeue`, `exited` and `own` from the staging-built `bin/monacoctl` in the primary clone, not from the worktree. Only `agents check` runs from the worktree. Keep old readers working by adding keys and leaving the old ones in their old shape. Why: a lane wrote a new key into the shared record from its worktree, the watch built from staging failed to decode it every round, and landing stopped for every lane.
- Run sim QA as scripted journeys (`docs/journeys` with `scripts/qa/journey.py`, test-without-building, data seeded through the backend API), never as improvised taps. No agent task runs 30 minutes without a pushed commit or a written result, and an investigation gets about 15. Before you take or restack a ticket, list its PRs' latest commit authors: a commit by someone else in the last 24 hours means a teammate owns it. Why: improvised QA took about two hours per agent, and two tickets were re-dispatched as dead while a teammate was still pushing to them.
- For a rewrite-era ticket (pot, cash out, fund, withdraw, holdings, mobile money screens), name the files to read with `git show c838bd24:<path>` in the owner's brief and say to port that behavior (rules, states, edge cases, UI flow, copy) into the current module architecture. Do not redesign, and do not copy its code patterns. Why: commit c838bd24 (2026-09-25) is the last working pre-rewrite build, and the operator wants its behavior integrated, not rewritten.
- Immediately before `monacoctl agents dispatch <n>`, run `gh pr list --state open --search "head:<n>-"` and `git ls-remote origin "refs/heads/<n>-*"`. A PR or branch by someone else under 24 hours old means a teammate owns the ticket, so skip it. Before you file a ticket for a staging failure, search open PRs for the failing test's name and its file. Why: an hours-old probe missed a teammate's four-PR stack, and a ticket was filed for a red test that a teammate's PR had fixed ten minutes earlier.
- A cap that runs one stage 0 check at a time is a stopgap for one run, not a policy. Cut the work per check: run only the packages that import a change, share build caches across worktrees, keep per-test probes out of the database hot path, and measure CPU-seconds and disk writes before and after. Restore the caps when the run ends. Why: parallel checks against Docker's test databases froze the machine three times, and the operator wants verification that does not burn the whole machine, not a permanent queue.
- To keep coding while `monacoctl agents check` runs, add a second worktree with the branch itself checked out (`git worktree add ../<n>-check-b <branch>`, with `.bin` symlinked) and run the check there in the background. Never check from a detached worktree, never put `gt modify` or a checkout in the same backgrounded command as the check, and run `git checkout` and `gt submit` as separate calls. Why: a check from a detached worktree measured PR size against staging instead of the Graphite parent, and a backgrounded branch switch raced a foreground checkout.
- Treat simulator QA that needs a signed-in app as agent work. `apps/mobile/qa/journeys/accounts.tsv` holds Privy test logins with fixed codes, and XCUITest can drive both the app and the iOS Settings app. Only a real third-party OAuth login or real mainnet money is the user's, so check an owner's hand-back against those two before it goes on the "Needs from Logan" list. Why: owners listed OTP sign-in and missing tap tools as operator items on an overnight run, and the operator asked why real QA was not being done.
- Run parallel work at the machine's real capacity: about 6 `agents check` slots and 4 Xcode slots. When load spikes, find the bug behind it (a broad `pkill`, a hung `xcodebuild`, Docker down) before you cut slots, restore capacity when load falls, and measure `uptime` and `memory_pressure` before and after any throttle. Cap the synthetic load of a load-test fix at 9 busy-loop processes. Why: cutting slots to 1 to 3 during a spike left 27 checks queued with 90% of memory free, and the spike's causes were bugs, not capacity.
- Name a worktree directory exactly after its branch, as in `git worktree add -b 573-flow-commands .worktrees/573-flow-commands origin/staging`, not by the bare ticket number. Why: the directory name tells the operator which branch is in it.

## Enforced by tooling

These original orders are now enforced. The hooks are `scripts/agent-guard.py`, `scripts/agent-guard-dispatch.py` and `scripts/agent-guard-dev-db.sh`. The check is the PR format check (`scripts/check-pr-format.py`), advisory since 2026-10-17.

| Order | Rule | Enforced by |
| --- | --- | --- |
| 3 | Graphite does all branching. No `git rebase` onto a local branch or interactively (`--continue`, `--abort` and a rebase onto a remote-tracking ref such as `origin/staging` are allowed), no `gh pr create`, no `gh pr edit --base`. | agent guard |
| 4, 14, 17, 20 | Template sections, `Part of #N` or `Closes #N` under Why, the "Needs from Logan" section on the last PR, Conventional Commit subjects, a title with no issue number or type prefix, and no SHA that is not an ancestor of the head. | PR format check, agent guard |
| 5, 21 | No build output is committed. | prose |
| 6, 18 | Stage 0 passes on the current tree before a push. Owners and verifiers run no full suite, no `-race` and no local mutation testing. | agent guard |
| 7 | No `gh run watch`, no `gh pr checks --watch` and no `sleep` over 10 seconds. | agent guard |
| 9 | A push never drops commits that the remote has and the local branch lacks. | agent guard |
| 10, 25 | Owner and verifier spawns are `pstack:poteto-agent` on `opus` or `sonnet`, only for a dispatched ticket. A verdict refuses the owner's model and `fable`. | dispatch hook, `monacoctl agents verdict` |
| 13 | Nothing turns durability off on the dev database container. | dev database guard |
| 16 | A plain `gt sync` does not run during a batch. | agent guard |
| 23, 24 | A test package warns at 10 seconds and fails at 20. A laptop run fails past 90 seconds. | `just test backend`, CI |
| 28 | Submit with `gt submit --stack --no-interactive --draft`, then set each PR with `scripts/pr-body.sh`. No `--publish` and no `gh pr ready`. | agent guard |
