- 2026-09-27: The `monaco-verifier` App is optional. The ruleset no longer requires `verify`. The agent guard still requires the latest `verify` status to be `success` before `gh pr merge`, and it accepts any poster.
- 2026-09-28: A changed file that no job filter owns now runs every job (the `unknown` filter), so editing `scripts/test-backend.sh`, `Justfile` or `docker-compose.yml` can no longer pass `ci-ok` with zero tests; those three also joined the `backend` filter. Added the `scripts` job for the `scripts/` Go module, which no PR job ran before. `docs/reference/**` left the `backend` filter: the pages are generated from backend code, whose changes already run the freshness check in `ready`. `docs.yml` deploys on a push to `main` only when its inputs changed. Corrected the `warm-cache` comment: `-shuffle=on` and `-coverpkg` are outside `go test`'s cacheable flags, so PRs reuse compiles, not test results (#814).
- 2026-09-29: Split CI into check stages (#831 B6 to B9). Pull requests run stage 1, the repo-wide checks with no tests, and reuse a green result when the diff's patch ID is unchanged. The merge queue runs stage 2, every job. The `backend` job split into `lint` (stage 1) and `backend` tests (stage 2). `mutation` left PR CI and runs only in the nightly. Added `monacoctl ci affected`.
- 2026-09-29: Added `go-cache.yml`, which saves the Go cache on a push to `backend-rewrite-3` or `main` that changes `go.mod` or `go.sum`. No `go-` cache existed for `backend-rewrite-3`, so every job downloaded modules cold, and proxy stream errors failed the Flake job and ejected #928 and #934 from the merge queue. `backend-test-env` now retries `go mod download` 3 times, and `lint` and `ready` restore the cache through it (#971).
- 2026-09-29: Swift warnings are errors (#980). The app, `MonacoTests` and `MonacoUITests` set `SWIFT_TREAT_WARNINGS_AS_ERRORS = YES` per target in `project.pbxproj`, and every SwiftPM build of `packages/mobile-core` (`just test mobile`, both `mobile-core` jobs, the `monacoctl agents check` swift row) passes `-Xswiftc -warnings-as-errors`. Never pass the setting on the `xcodebuild` command line, and never set `treatAllWarnings` or `unsafeFlags` in `Package.swift`: Xcode builds the local `MonacoCore` package with `-suppress-warnings`, so either fails with `conflicting options '-warnings-as-errors' and '-suppress-warnings'`. `swift-openapi-generator` is pinned at exactly 1.13.0 because 1.13.1 splits the generated code into files that each carry unused `public import` lines, which warn ([apple/swift-openapi-generator#946](https://github.com/apple/swift-openapi-generator/issues/946)). Lift the pin with the release that closes that issue.
- 2026-10-02: `monacoctl agents batch` no longer counts an overlap inside `[batch] shared` (#1342). `flows.tsv` and the backend `CHANGELOG.md` merge with `merge=union`, `agents check` keeps `flows.tsv` sorted by id, and each module registers its events in its own `internal/events/<module>_registrations.go`. [Shared files](../ci.md#shared-files) lists the globs.
- 2026-10-02: The `backend` job runs as three parallel legs (`short:1/2`, `short:2/2`, `rest`) and a `backend-report` job gates the merged output (#1595). One runner took 433 s on queue run 37031732879 (7.9 min stage 2), longer than every other stage 2 job, and its passes do not depend on each other. Each pass writes `go test -json` and coverage files that the report job concatenates as the single script did. Shards split packages by longest processing time over `apps/backend/.test-shards.tsv`; refresh it with `monacoctl test-shards update --from <json>...` when the split drifts.
- 2026-10-02: A new error code no longer edits a file every area shares. Each `internal/errs/codes_<area>.go` has its own `testdata/codes_<area>.golden` in place of `all_codes.golden`, and `monacoctl gen errors` writes the `ErrorCode` schema as the whole generated `api/spec/error_codes.yaml` in place of a marked block in `base.yaml`. Both globs are in `[batch] shared`, so `monacoctl agents batch` no longer serialises tickets that each add a code.
- 2026-10-03: `monacoctl agents land-stack` checks the bottom PR's mergeability locally (#1660). It fetches the trunk and the bottom head SHA into the stack's worktree and runs `git merge-tree --write-tree origin/<trunk> <head>`. Exit 1 is a conflict, and it labels nothing. It no longer waits up to 90 s for GitHub's `potentialMergeCommit` to sit on the trunk tip. GitHub recomputes that value lazily, so after a trunk move a clean stack could not queue until a restack and push reran stage 1.
- 2026-10-03: CI's per-package fail budget rose from 40 s to 60 s after queue runners slowed about 2x from 04:29 UTC and `cmd/monacoctl/verify` timed 39 to 45 s with every test passing (#1709). #1698 cuts that package's time.
- 2026-10-03: `monacoctl agents` reads machine capacity from `<git common dir>/.monaco/agents.local.toml` (#1674). `lanes`, `[check] slots` and `[dispatch] max_load` there override the tracked `.monaco/agents.toml` for every worktree of one clone, and any other key fails. Capacity had been the same for every teammate, and an edit to the tracked file reached neither new worktrees nor owners' `agents check` runs.
- 2026-10-03: `monacoctl agents land-stack` arms a stack whose stage 1 or `verify` is still running (#1661). It writes `armed` to the owner record and labels nothing, and `agents watch` lands the stack the round nothing waits, or disarms it once when stage 1 or `verify` fails. Agents had invented their own waits between submit and land, such as session cron jobs and verifiers telling the root to rerun `land-stack`, because the guard hook blocks CI wait loops.
- 2026-10-03: `cmd/monacoctl/verify` tests take 3.6 s under the queue flags, down from 8.4 s, and 12 s of CPU at `-cpu=4`, down from 30 s (median of three interleaved local runs; #1698). The queue had timed the package at 41.8 s on a slow runner, over the 40 s fail line. A fake clock advanced by an hour fired the 10 ms log-poll ticker 360,000 times, and the never-healthy stack test waited out a real 2 s budget. Tests that never call the API no longer start a served app.
- 2026-10-03: Every `monacoctl agents watch` reports a stack's landing or ejection, not only the one that settled it (#1681). Settling cleared `queued`, so other watches on the machine skipped the record and never printed `stack #N landed`. The owner record now keeps `settled` (outcome, line, time), and each watch started before that time prints the line once. `land-stack` clears it when it queues again. A watch ejection, streamed or `--once`, now releases the stack the way `dequeue` does before it clears `queued`: it removes `merge-queue` from every PR and waits until no open `gtmq_` draft lists them. It had left the label on the upper PRs, where `dequeue` could not reach them (#1720 after #1719 was ejected). In the same change, a removed `merge-queue` label no longer reads as dropped while an open `gtmq_` draft lists the PR, the `run land-stack again` advice is held back while Graphite runs `queue_concurrency` drafts (set in `.monaco/agents.toml`), and a record write keeps keys that the running `monacoctl` does not know, so an older build no longer wipes `armed`.
- 2026-10-03: `cmd/monacoctl/verify` parses `api/openapi.yaml` once per test binary instead of three times per served app (#1701). After #1715 it still spent most of its `-race` CPU in kin-openapi, which parsed the same spec in `testkit.HTTP`, `httpx.Handler` and `ratelimit.Load` on every `scenario.Serve`. `httpx.LoadContract` now returns a read-only `*httpx.Contract` that `httpx.HandlerFor`, `ratelimit.FromDocument` and `testkit.HTTPAgainst` share. `scenario.Serve` parses once per call, or not at all with `scenario.WithContract`, which replaces `WithSpec`, and `verify` loads the contract once in `TestMain`. A package-level cache would have been simpler, but `gochecknoglobals` rejects one outside `main_test.go`.
- 2026-10-03: `go-cache.yml` saves the Go cache on every push to `staging` or `main`, not only on a `go.mod` or `go.sum` change, and compiles the test binaries with `scripts/test-backend.sh`'s build flags first, so PR test legs start with a warm build cache. A prune job keeps one `go-` cache per ref. `ci-warm.yml` also saves the mobile cache on a push to `staging`. `staging` is the default branch, so every PR can restore what it saves.
- 2026-10-03: `PR format (title, body and commits)` is no longer a required check on `staging`, and `land-stack` and `agents watch` no longer wait on it. It failed #1789 and #1773 on the exhausted `GITHUB_TOKEN` installation rate limit, not on their bodies, and `scripts/pr-body.sh` already runs the same check locally before it sets a body.
